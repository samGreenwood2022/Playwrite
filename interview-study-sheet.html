Test Automation — Interview Study Sheet

Best practices implemented in a Playwright + TypeScript + Cucumber BDD framework — what to explain, where it lives in the code, and why it matters. Lead with the principle, point to the code, then say why.

Open with these three
Star talking point

Independent, isolated tests

Before hook → fresh context

A new browser context + page per scenario. No shared state, no order-dependency — the single biggest cause of flaky suites.

Star talking point

Auth via storage state

BeforeAll → .auth/user.json

Sign in once, reuse everywhere. Atomic temp-file + rename write survives parallel workers; 1-hour TTL. Cookies never committed.

Star talking point

Network edge-case injection

page.route()

Force states the live API won't give on demand — 500, empty, dropped, slow, malformed — to test resilience deterministically.

Architecture & patterns

Structure & separation

  • ✓
    Page Object Model tests/pages/*Locators + actions live in the object; specs never touch selectors. One place to fix when the UI changes.
  • ✓
    Separation of concernsSite-wide bits (logo, a11y scan, visual-diff engine) in BasePage; header Sign-in there, sign-in form in LoginPage.
  • ✓
    BDD with Gherkin *.featureGiven/When/Then read as living documentation a non-technical stakeholder can follow.
  • ✓
    Thin steps / SRPSteps delegate to page objects; network trickery isolated in network-stubs.ts, lifecycle in world.ts.
Test design

Data & execution

  • ✓
    Data-driven Scenario OutlineExamples tables + DataTables — one outline covers many pages/rows.
  • ✓
    The spec owns expectationsNav labels/hrefs, phone numbers live in the feature table — not hardcoded in the page object.
  • ✓
    Tag-driven runs@smoke @regression @accessibility @authenticated @stub-* slice the suite for fast feedback.
Reliability

Anti-flakiness

  • ✓
    Web-first assertionsexpect(locator).toBeVisible({timeout}) auto-retries — no manual polling loops.
  • ✓
    Event-based waits, not sleepswaitForResponse / requestfailed / networkidle. The lone 500 ms wait (paint settle) is deliberate and commented.
  • ✓
    Semantic, stable locatorsgetByRole, data-cy, component tags over auto-generated IDs; phone link by its action attr.
  • ✓
    Live-site resilienceSearch retries/re-types before reloading; interstitial overlays dismissed in one central place.

Auth & performance

State handling

  • ✓

  • ✓

  • ✓

Engineering & CI

Pipeline & tooling

  • ✓

Know your gaps

Naming limitations reads as senior. Pre-empt these — each with an honest "next step".

▲
Cross-browser: configured, not exercisedThe Playwright config lists chromium/firefox/webkit, but the Cucumber runner always launches chromium. Next: parameterise the browser.
▲
A11y reports, doesn't assertAxe writes an HTML report but nothing fails on violations. Next: assert violations against an agreed threshold.
▲
Custom pixelmatch vs built-inHand-rolled diffing instead of toHaveScreenshot(). Justify the control/runner reasons — and know the built-in is the standard choice.
▲
Baselines auto-pass on first runA missing baseline is created and passes. Commit a Linux baseline so CI truly compares — the workflow already uploads snapshots for this.
In the room

"Tests must be independent, so we build a fresh browser context per scenario in the Before hook — that removes order-dependency, the number-one cause of flaky suites."  Principle → code → why. Every time.
